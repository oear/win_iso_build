# Experimental LTSC 安装后验收

这条路线制作的是**非官方实验性混合镜像**。保留 `EnterpriseS` 或出现目标构建号，都不能证明它属于微软支持的 LTSC，也不能证明后续更新兼容。`26340.9616` 是待核验的目标值；仅凭此前聊天中的 KB 编号、论坛截图或版本号，不应批准构建或安装。

先在可销毁的虚拟机中验收。使用有合法授权的原始 Enterprise LTSC 2024 简体中文 x64 镜像，保存来源、SHA256、补丁来源、固定代码提交、包元数据和完整构建日志。不要加入激活工具，不要关闭 Defender、UAC、签名验证或更新服务，不要先运行权限修复或右键菜单修复工具。由干净安装结果判断是否接受该路线。

## 采集脚本怎么运行

安装完成并登录新建的测试账户，在**普通、未提升**的 Windows PowerShell 5.1 或更新版本窗口中运行。脚本必须在被测 Windows 中执行；macOS 构建主机无法替代这一步。

```powershell
.\Test-InstalledSystem.ps1 -ExpectedBuild '26340.9616' -OutputPath '.\acceptance-before-update.json'
```

目标构建尚未独立核验时，省略 `-ExpectedBuild` 即可收集实际版本；参数只用于比较期望值。输出目录必须存在，输出文件必须是新文件。按现有组织策略运行已经审阅的脚本，不要为了运行它全局修改执行策略。若下载标记阻止执行，应先检查脚本和对应哈希，再按组织允许的方式运行。

脚本只在实际用户目录、桌面和文档中各创建一个随机临时目录，完成小文件创建、读取、重命名和删除，然后清理自身文件。它不会创建缺失的系统用户目录、递归删除未知内容、改 ACL、写注册表、触发 Windows Update、读取 sing-box 配置或执行发现的二进制文件。如果清理失败，JSON 会保留探针位置；先检查该位置，再手工清理自身探针。

报告中的 `Passed` 只适用于对应的微型检查。`Observed` 表示取得了证据，`NotRun` 表示未完成检查。`OverallStatus` 只有 `Failed` 或 `ManualRequired`，`AcceptanceConfirmed` 始终为 `false`，防止把资料采集当成系统验收通过。退出码 `0` 表示已完成采集且未发现自动检查失败，`1` 表示发现自动检查失败；其他脚本错误也应作为未完成处理。提升权限运行会被标为失败，且跳过写入探针，以免管理员权限掩盖普通用户的故障。

JSON 含用户名、SID、本机目录和 ACL，应在分享前检查并脱敏。脚本不输出产品密钥、代理配置、远端地址、ShellNew 命令/数据、文件关联 Hash 或更新事件完整消息。网络凭证和私有配置请放在仓库以外，也不要粘贴进 issue、提交、Actions 日志或验收附件。

## 验收门槛与证据

每一项都记录测试时间、VM 快照标识、实际构建号、操作与结果。未运行、未支持或缺少证据的项目不能记为通过。保留正常 LTSC 原版的对照 VM，使用相同虚拟硬件、账户类型和测试网络；发现差异时先保全证据再定位原因。

| 项目 | 自动采集能说明什么 | 必须人工验收的内容 |
| --- | --- | --- |
| 版本与版本类型 | 当前构建号、修订、`EditionID`、x64 架构、安装语言 | 核对 `winver`、系统信息、DISM 在线版本类型/包状态，以及构建清单；微软支持状态依官方发布信息单独判定 |
| 用户目录 ACL | 当前 SID、注册配置文件路径、目录 ACL、普通用户小文件读写 | 新账户登录，用户目录/桌面/文档实际操作；重启后复测；禁止先用 `takeown`、`icacls /reset` 或全盘赋权掩盖问题 |
| 右键“新建”菜单 | `.txt` 的有效注册关联及 ShellNew 创建机制是否存在 | 资源管理器实际菜单、创建文本文档和文件夹、保存/重命名/删除；退出登录或重启资源管理器后重复 |
| Windows Update | 服务状态、部分数字策略、近 7 天最多 30 条事件元数据 | VM 快照后手工扫描、审核候选包、明确选择测试更新、安装与重启，检查失败/回滚/版本类型意外改变 |
| sing-box / Reality | 常见路径的文件存在、SHA256、可用的文件版本资源、进程存在 | 在私有合法端点下验证客户端版本、Reality 握手、TCP/UDP/DNS/TUN/IPv4/IPv6、重连与重启 |
| 构建安全性和授权 | 本采集器不作安全/授权修改 | 校验输入/产物哈希、固定代码版本、包来源/签名/适用性和 DISM 日志；保留安全默认设置与合法许可证 |

### 用户目录与资源管理器

1. 干净安装后创建新用户。用该账户的普通窗口运行采集器；不要使用旧配置文件覆盖新目录。确认报告中 SID 与 `ProfileList` 路径一致，桌面/文档若重定向到 OneDrive 或其他位置，按报告的实际位置检查。
2. 分别在 `C:\Users\当前用户`、实际桌面和文档目录右键，检查“新建”是否有文件夹和文本文档。建 TXT，输入文字、保存、重命名、删除，再创建/删除文件夹。全过程不应出现要求管理员权限的提示。
3. 保存菜单截图和操作结果；注销/登录或重启后重复。文本注册键存在只能说明关联候选存在，不能代替 Explorer 实际行为。不要将 `C:\Users`、`C:\Windows` 或 `C:\Program Files` 的写入规则当作个人目录的对照标准。
4. 如果失败，保留该 VM 快照、采集 JSON 与具体失败目录/动作。在原版 LTSC 对照 VM 重复同一操作。权限根因未确认前，本路线不得标为通过。

### Windows Update

采集器不会启动扫描、下载、安装或升级。服务处于停止状态可能属于正常触发启动行为；日志为空也不能说明兼容。

1. 断开不必要的外部资源，保留安装后快照和 `before-update` 采集报告。记录合法授权状态及实际版本类型，不保存产品密钥。
2. 在 VM 中人工连接允许的更新网络并打开 Windows Update。先查看提供的更新类型、KB/版本及发布通道，保存截图。不要不加审核地加入 Insider 通道、接受版本类型转换或整机功能升级。
3. 选择已验证适用的更新执行一次真实安装，保存 Windows Update/CBS/DISM 必要日志。日志可能包含本机私有信息，分享前脱敏。记录是否成功、错误码、回滚和重启次数。
4. 重启后运行新报告文件，例如 `acceptance-after-update.json`，重复 ACL、Explorer 和网络测试。不能仅凭“检查更新成功”判定长期可维护性；至少一次实际更新安装、重启与回归验收仍然必要。
5. 若当前没有已验证且适用的更新，本项记为“未验证”，不强行安装不适用启用包或更改更新通道。保留快照，之后用已验证的更新继续验收。

### sing-box / Reality 网络

采集器不连接远端、不读取配置、不获取命令行，也不启动发现的二进制文件。官方 Go 二进制可能没有 Windows 文件版本资源，此时 JSON 的 `FileVersion` 为空是预期的证据缺口。取得可信来源并校验哈希后，在私有测试环境人工运行 `sing-box version`，记录客户端精确版本。仅有进程或 TUN 网卡不能说明兼容。

凭证、UUID、私钥、访问令牌和私人端点应在仓库外私下填写。用自己有权使用的测试服务做以下测试，避免用公开陌生端点作判断。TUN 配置若确实需要管理员权限，应在网络测试阶段明确记录该需求；ACL 与 Explorer 验收仍必须在普通账户下完成。

| 场景 | 最少证据 |
| --- | --- |
| Reality 握手与重连 | 客户端/服务端版本、脱敏错误码、成功连接与断开后重连结果；不要提交私密配置 |
| TCP | 小下载和持续连接各一次，记录连接成功、断流/重连、实际所走的出站 |
| UDP | 仅在所选协议/出站支持 UDP 时测试自己的 UDP 服务，记录是否发生回退；不支持则明确标记 |
| DNS | 私有测试域名的解析结果，直连/代理/TUN 下预期路径一致；确认错误 DNS 或循环配置没有被当成系统故障 |
| TUN | 记录启用所需权限、路由和 DNS 行为，切换启用/禁用后验证恢复；不要批量删除系统防火墙或路由规则 |
| IPv4 / IPv6 | 分别使用可控双栈目标；测试网络没有 IPv6 时记为未验证，不能据此宣布 IPv6 兼容 |
| 重启 / 网络变化 | Windows 重启后、断网/恢复后再测握手、DNS、TCP 和支持的 UDP；记录是否能按预期恢复 |

失败时保留脱敏日志，并在原版 LTSC 对照 VM 用同一客户端版本和同一合法端点复测。区分客户端配置、服务端协议、网络环境与系统差异；没有实测结果时，本项仍为未验证。

## 构建安全性复核

安装前核对基础 ISO 和每个包的 SHA256、官方来源/签名、语言/架构/版本适用性、固定提交与可审阅脚本。微软原始 ISO、独立包及第三方脚本的信任边界要分别记录，第三方分卷哈希一致不等于微软原件真实性已经成立。

保留 DISM 包枚举、适用性检查和集成日志；要求目标包实际处于预期状态，而不是只改注册表的构建标识。发生适用性拒绝、签名校验失败、来源不明或必须强制添加才能成功时，停止该实验候选并保留证据。不要通过激进精简、禁用安全组件、改权限或绕过授权使验收“变绿”。

产物在干净安装、上述用户目录/Explorer 测试、一次真实适用更新及网络测试结束前，只能标注为“实验候选，未完成运行时验收”。即使全部实验验收通过，仍须保留“非官方混合镜像”标识，不能改称微软支持的 LTSC 版本。
